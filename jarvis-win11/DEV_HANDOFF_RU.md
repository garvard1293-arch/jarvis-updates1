# JARVIS Windows 11 — контекст для продолжения разработки

**Дата снимка проекта:** 2026-10-25 15:26 (Europe/Riga)

Этот документ подготовлен для того, чтобы загрузить архив проекта в новый разговор и продолжить разработку без повторного объяснения уже принятых решений. Перед изменениями прочитай этот файл и `README.md`, затем осмотри исходники и внеси только нужные изменения.

## Цель и устройство проекта

JARVIS — настольный русскоязычный голосовой помощник для Windows 11. Целевой компьютер пользователя: NVIDIA GTX 1080 Ti, Intel Xeon E5-2660 v4, 16 GB RAM. Проект — исходники Python/PySide6, а не собранный `.exe`.

Основные файлы:

- `jarvis_app.py` — главное окно, чат, локальный wake-word/распознавание Vosk, голосовой вывод Windows SAPI, разрешённые действия Windows, настройки Ollama/Gemini.
- `studio.py` — отдельная Студия кода/игр: генерация файлов, предпросмотр, проверки путей/расширений, подтверждение сохранения, подтверждение перед открытием проекта в движке.
- `README.md` — установка и использование.
- `install.bat`, `start.bat` — базовая установка и запуск.
- `setup_openjarvis_backend.bat` / `.ps1`, `start_openjarvis_backend.bat` — необязательная установка и ручной запуск локального OpenJarvis backend.
- `previews/` — снимки интерфейса; это рендеры Qt в Linux headless-среде, не снимки с Windows-компьютера пользователя.

## Уже реализовано

1. Тёмный GUI на PySide6: боковая навигация, анимированный круг-орб, статус микрофона/модели, чат, настройки.
2. Русское wake-word «Джарвис» распознаётся офлайн через Vosk. Голосовой ответ идёт через Windows SAPI при наличии русского голоса.
3. Диалоговая модель выбирается как Ollama локально или Gemini API. Gemini key хранится через Windows Credential Manager (`keyring`), а не в JSON. Настройки приложения размещаются в `%APPDATA%\JarvisAssistant\settings.json`.
4. Студия поддерживает Godot 4, Unity, Unreal Engine 5, GameMaker, Pygame и Roblox Studio. Текстовые файлы сначала показываются в предпросмотре. Сохранение и перезапись требуют явного подтверждения; блокируются опасные пути, `.git`, `.venv`, `node_modules`, файлы секретов и исполняемые расширения. Открытие проекта в движке требует дополнительного предупреждения, потому что сам редактор может выполнять/компилировать код.
5. В Студии доступны прямой backend Ollama/Gemini и необязательный OpenJarvis agent. OpenJarvis backend загружается на закреплённом commit `40092da25efb2288f2650d0380d5224d3c46b9a1` (Apache-2.0), слушает только `127.0.0.1:8765`, разрешает только `file_read`, `file_write`, `think`, а доступ ограничен `%APPDATA%\JarvisAssistant\AgentStaging`. Нет shell, Python interpreter или MCP tools; агент выдаёт файлы через staging, после чего приложение показывает предпросмотр. Setup и запуск OpenJarvis не тестировались на реальном Windows ПК.
6. В главном окне добавлена кнопка «Разрешить свободу действий». По умолчанию выключена, при включении показывает подтверждение и сохраняет флаг `freedom_mode`. Расширенный allowlist добавляет только открытие известных папок пользователя (Рабочий стол, Документы, Загрузки, Изображения, Видео, Музыка, `JarvisProjects`), Paint и Snipping Tool. Запуски идут с `shell=False`. Это не даёт произвольный доступ к ПК: нет команд PowerShell/cmd от модели, произвольного запуска программ, изменения/удаления файлов или автоматического запуска кода. Режим отключается той же кнопкой.
7. Студийный system prompt разрешает разработку собственных игр и допустимых модификаций, но запрещает читы в мультиплеере, обход/уклонение от античита и инъекции в игровые процессы.

## Проверки, уже проведённые в sandbox

- `python3 -m py_compile jarvis_app.py studio.py` проходил после последней доработки.
- PySide6 Qt offscreen smoke-tests проходили: главное окно и Studio создаются, Студия показывает шесть движков, голосовая фраза открытия Studio распознаётся маршрутизатором, небезопасные пути/секреты/исполняемые файлы отклоняются, сохранение работает только при подтверждении.
- Для кнопки свободы действий проверено: она по умолчанию выключена; после тестового подтверждения сохраняет opt-in; Paint и папки открываются только в разрешённом режиме; команды передаются через `shell=False`; произвольная команда не выполняется. В тестах вызовы запуска приложений были подменены, реальные приложения не запускались.
- OpenJarvis staging adapter проверен с подменённым HTTP ответом: файлы из staging попадали в предпросмотр, временная папка затем удалялась.
- TOML безопасной конфигурации OpenJarvis проверен парсером Python `tomllib`.
- ZIP целостность проверялась через `unzip -t`.
- **Само приложение, Vosk аудио и инсталляторы не запускались на Windows 11 пользователя.** Linux offscreen screenshot не доказывает совместимость с Windows.

## Ограничения и что ещё не сделано

- Это не полноценный автономный агент и не аналог ChatGPT по интеллекту. Локальная модель, например Qwen3 8B, ограничена качеством/скоростью и VRAM; для трудных запросов предусмотрен Gemini API.
- Голосовая активация/команды — Vosk small Russian, распознавание длинных фраз может ошибаться. Whisper ещё не интегрирован.
- Code Studio создаёт проектные файлы по запросу, но не индексирует автоматически существующий проект целиком и не делает полноценный цикл «прочитать большой проект → отредактировать → запустить тесты → исправить ошибки».
- JARVIS сам не исполняет generated code и не имеет произвольного shell. Не расширять это до бесконтрольного системного агента. Любое расширение действий должно быть отдельным, ограниченным allowlist, с понятным пользовательским подтверждением.
- Поддержка движков означает шаблоны/инструкции и открытие установленного редактора; сами движки не входят в архив.
- Настоящая Windows-проверка, особенно запуска Vosk, микрофона, Gemini, всех путей/команд Windows и OpenJarvis setup, ещё нужна.
- Упаковка в автономный `.exe`/инсталлятор отсутствует.

## Что логично сделать следующим

1. Пользователь должен проверить архив на своём Windows 11 ПК. Сначала проверить `install.bat`, `start.bat`, микрофон и команды без расширенного режима; затем протестировать кнопку расширенных действий и запуск Studio. Записывать ошибки и исправлять по traceback/скриншоту.
2. Проверить при первом Windows-запуске, что `Path.home()` и пути папок на русской локализации совпадают с реальными known folders. При необходимости перейти на Windows Known Folder API вместо сборки папок через `Path.home()`.
3. Проверить скачивание Vosk, работу SAPI русского голоса и точное имя Gemini model для текущей доступности в аккаунте пользователя.
4. Проверить безопасный installer OpenJarvis в чистой Windows среде: наличие `pyproject.toml`, Apache LICENSE, `uv sync`, загрузка `qwen3:8b`, старт `/v1/chat/completions`, применение `security.allowed_dirs` к `AgentStaging`. Не выдавать успех, пока это реально не проверено.
5. Если пользователь хочет более умную работу с уже существующими проектами — спроектировать отдельный read-only context picker и дифф/patch review, не разрешая агенту напрямую перезаписывать/запускать файлы.
6. При каждой доработке запускать `py_compile`, offscreen тесты и `unzip -t`, а после менять архив.

## Как продолжить в новом разговоре

Загрузить полный архив `Jarvis-Windows11-Project-Continuation.zip` и написать, например:

> «Продолжим разработку JARVIS. Сначала прочитай DEV_HANDOFF_RU.md и README.md из архива и проверь текущее состояние файлов. Затем реализуй/исправь: [задача]. Не переписывай то, что уже работает.»

В архиве нет Gemini API-ключа, пользовательских настроек, Windows Credential Manager данных, Python venv, Vosk model binaries или других личных секретов. Их не нужно добавлять в будущий архив.
